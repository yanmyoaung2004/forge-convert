  `ForgeError::Unsupported{capability:"pdf-to-image"}`; CLI `Render` arm at
  `apps/cli/src/main.rs:670-687` surfaces it (exit 8); `info` notes ADR 009 at `:698`.
  No desktop render command exists (`api.ts` has `pdfPageCount` but no render call).
- Renderer candidates (`cargo search` 2026-10-04, all UNVERIFIED — license/MSVC/API TBD in spike):
  `hayro 0.8.0` (pure-Rust rasterizer), `pdfium-render 0.9.4` (+ `pdfium-bundled`),

- Diagram: `serialize.ts` (SVG string, viewBox from `contentBounds`), `export_svg_file`

## Slice A — styled QR (no new dep)

- `encode_qr` += `colors: Option<(QrColor, QrColor)>` (hex `#rrggbb`, validated; default black-on-white
  = today's behavior). Render `Rgb<u8>` with `dark_color/light_color`; SVG passes hex through
  `svg::Color(custom)`. Bad hex → `InvalidConfiguration` (CLI exit 2).
- Logo embed: `logo: Option<&[u8]>` (bounded read via caller) composited center at ≤20% of canvas
  via `imageops::overlay` (PNG only; SVG refuses logo with clean error — vector has no raster rule).
  EC-H recommended with logo (docs, not forced).
- CLI: `qr [--dark #…] [--light #…] [--logo file]`; `qr-batch` same flags; desktop: two color
  inputs + logo picker in QR panel (preview via existing Generate path).
- Tests: custom-color PNG decodes via `decode_qr` round-trip (rqrr is color-tolerant — assert it);
  bad hex → clean error; logo PNG still decodes at EC-H; SVG+logo → clean refusal.
- **Commit:** `feat(qr): styled QR - custom colors, logo embed`

## Slice B — PDF renderer (spike first, one new dep max)

- Spike (throwaway, before committing): `cargo add hayro`, verify license, MSVC build,
  render vendored test PDF page → PNG bytes → `CanonicalImage`.
  Fallback order: `hayro` → `pdfium-render` (+bundled binary license check) → reject `mupdf` (AGPL).
  Record winner + license in `docs/PLAN.md` dep table before wiring.
- `forge-pdf`: `HayroRenderer: PdfRenderer` (`render(bytes, pages, dpi)` → `Vec<CanonicalImage>`,
  dpi clamp 1–1200 like CLI; per-page failures structured `PdfRenderFailed`, never panic).
  Keep `StubPdfRenderer` behind a feature or delete on success (no shims).
- CLI: `render` arm goes live (same `--format/--dpi/--pages` grammar, `{stem}-p{page}.{ext}`
  naming via engine rules + `record_history("render", …)`); exit 8 only for genuinely
  unsupported inputs now.
- Desktop: `render_pdf {input, pages?, dpi?, format?}` command + PDF tab "Render pages" row
  (reuse `pickFiles` + result reveal pattern).
- Tests: render vendored PDF page → PNG magic + expected dims at 72dpi; garbage bytes →
  `PdfReadFailed`; out-of-range page → `InvalidConfiguration`.
- **Commit:** `feat(pdf): render pages to images - <winner-crate>, render CLI, desktop row`

## Slice C — diagram PNG export (frontend + thin Rust)

- Pure-TS: serialize current doc → SVG string (existing `serialize.ts`) → rasterize via
  `createImageBitmap` + `<canvas>` at 1x/2x scale → PNG blob (no new deps; DOM path, not bun-smoked).
- Rust: reuse `export_svg_file` atomic-write pattern as `export_png_file {path, png_base64}`
  (refuse empty payload; `write_atomic`); or write via dialog `save()` + existing commands —
  pick the thinner path in-slice, never both.
- `DiagramTab`/`CodeViewer`: "Export PNG" button next to Export SVG + scale select;
  result reveal via `revealInFolder`.
- Tests: `vite build` + manual open (canvas path is DOM-only, not bun-coverable — note in plan);
  SVG validity assertions stay in diagram smoke.
- **Commit:** `feat(diagram): PNG export - rasterize + export button`

## Non-goals

- Explicit Micro-QR versions, non-QR barcodes, camera scanning, cloud/dynamic QR,
  OCR for scanned PDFs, `.doc` legacy output, Mermaid import (later), collab/cloud.

## Risks (facts)

- Renderer dep: license + MSVC + `CanonicalImage` conversion all UNVERIFIED — spike decides,
  never guess; `mupdf` expected AGPL reject.
- `hayro 0.8` API shape unknown — verify against vendored sources after `cargo add`.
- Logo embed hurts scannability — EC-H docs + round-trip test at default logo scale.
- Canvas rasterize needs DOM — untestable in bun smoke; manual verify + `vite build` gate.
